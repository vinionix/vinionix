# Portfolio Map

This document explains how the repositories in this GitHub account fit together as a technical portfolio.

## Current direction

The main professional direction is **AI Engineering**, with emphasis on generative AI, LLM systems, evaluation, agents and software engineering foundations.

The portfolio also preserves projects in systems programming, networking, infrastructure and game development because they show the technical path that supports the current AI work.

## Flagship AI projects

### From Zero to MiniGPT
A long-form project that rebuilds the path from mathematics and neural-network fundamentals to a small decoder-only Transformer and, later, a complete LLM system.

What it demonstrates:
- mathematical learning applied to code;
- model internals;
- experimentation and tests;
- progression from foundations to LLM engineering.

### CPU LLM Lab
A CPU-only benchmark lab for small local language models answering questions grounded in a controlled document base.

What it demonstrates:
- LLM evaluation;
- grounded generation;
- hallucination/refusal tests;
- latency and token measurements;
- quality versus infrastructure cost.

### AgentOps Triage
A staged technical-support triage workflow designed to evolve toward model-backed agents.

What it demonstrates:
- FastAPI and Pydantic;
- agent/workflow orchestration;
- separation between deterministic logic and LLM integration;
- domain knowledge from support/network operations.

## Systems and software engineering foundations

Repositories such as `My_minishell`, `Cpp_list`, `My_Philosophers`, `My_push_swap`, `Mylib_c` and `Irc` document the systems-programming foundation developed through 42 Rio.

They cover:
- processes and file descriptors;
- concurrency and synchronization;
- sockets and network protocols;
- memory management;
- data structures and algorithms;
- object-oriented programming in C++.

## Infrastructure and networking

`ccna-network-labs` and `Inseption` document networking and infrastructure practice, including TCP/IP, troubleshooting, containers, Docker Compose and service isolation.

## Product and application projects

Projects such as EasyBarber, Bomb-Arena and smaller application experiments show experience outside the systems/AI path and are useful as evidence of product-oriented software development.

## Documentation principle

The repositories are documented conservatively: planned work is labelled as planned, limitations are made explicit, and READMEs should describe the code that exists rather than inflate the project with unimplemented features.
